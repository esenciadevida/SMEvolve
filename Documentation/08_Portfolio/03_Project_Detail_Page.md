# SMEvolve Portfolio Specification
## Part 3 – Project Detail Page

**Project Name:** SMEvolve

**Website:** https://smevolve.tech

**Version:** 1.0

**Document Type:** Project Detail Page Specification

---

# Purpose

This document defines the structure, content, layout, and implementation requirements for individual portfolio project pages.

Every project page should explain not only what was built, but why it was built, how it solved the client's problem, and how similar businesses can benefit from a comparable solution.

---

# AI Implementation Instructions

Before implementing this page:

1. Read the AI Constitution.
2. Read the PRD.
3. Read the Information Architecture.
4. Read the Design System.
5. Read the Brand Messaging document.
6. Read the Portfolio Master Specification.
7. Follow this document exactly.

Do not invent clients, business outcomes, statistics, testimonials, awards, or measurable results.

If a project is fictional or used as a demonstration, clearly identify it as a concept project or sample project.

---

# Business Goal

Build confidence in SMEvolve's ability to deliver high-quality digital solutions while encouraging visitors to enquire about similar projects.

---

# User Goal

Visitors should quickly understand:

- What the project was
- What problem it solved
- How it was implemented
- Which technologies were used
- Whether SMEvolve can build something similar

---

# Page Structure

Each Project Detail page should follow this order.

1. Hero
2. Project Overview
3. Project Gallery
4. Business Challenge
5. Solution Delivered
6. Key Features
7. Technologies Used
8. Related Services
9. Next Project Navigation
10. Final Call To Action

# Project Overview

Summarize:

- Project purpose
- Industry
- Project type
- Services provided
- Technologies used

Present these details in a clean summary layout.

---

# Project Gallery

Display:

- Desktop screenshots
- Mobile screenshots (if applicable)
- Feature highlights
- Interface previews

Support future image expansion.

---

# Business Challenge

Explain:

- The client's challenge
- Business context
- Goals of the project

Focus on the problem rather than technical implementation.

---

# Solution Delivered

Describe how SMEvolve approached the project.

Cover:

- Planning
- Design
- Development
- Testing
- Deployment (if applicable)

Keep the explanation business-focused.

---

# Key Features

Present the major project features using reusable feature cards.

Examples:

- Responsive design
- Dashboard
- Online payments
- Booking system
- Inventory management
- User authentication
- Reporting
- AI functionality

Only display features relevant to the project.

---

# Technologies Used

Display technologies using reusable technology badges.

Examples:

- Laravel
- WordPress
- React Native
- Tailwind CSS
- MySQL
- REST APIs
- Firebase

Only include technologies actually used.

---

# Related Services

Recommend services closely related to the project.

Examples:

- Website Development
- Mobile App Development
- API Development
- Website Maintenance

Encourage visitors to continue exploring.

---

# Next Project Navigation

Provide navigation to:

- Previous Project
- Next Project

Support future portfolio expansion.

---

# Final Call To Action

Encourage visitors to discuss a similar project.

Primary CTA

Discuss Your Project

Secondary CTA

Book a Consultation

---

# Components

Reuse shared components wherever possible.

Suggested components include:

- Project Hero
- Project Summary
- Gallery
- Feature Grid
- Technology Badges
- Related Services
- CTA Banner

---

# Responsive Behaviour

Ensure:

- Responsive gallery
- Flexible feature layouts
- Mobile-friendly navigation
- Readable spacing
- Optimized images

---

# Accessibility

Every project page should:

- Use semantic HTML
- Include descriptive alt text
- Support keyboard navigation
- Maintain heading hierarchy
- Meet WCAG AA standards where practical

---

# SEO

Each project page should include:

- Unique page title
- Meta description
- Canonical URL
- Open Graph metadata
- Structured data where appropriate
- Internal links to related services

---

# Analytics

Track:

- Project views
- Gallery interactions
- CTA clicks
- Related service clicks
- Quote requests

---

# Acceptance Criteria

A project page is complete when:

- All required sections are implemented.
- Images are optimized.
- Components are reusable.
- Accessibility requirements are met.
- SEO principles are followed.
- Navigation works correctly.
- Calls to action are clearly visible.

---

# Revision Policy

Future project pages should follow this structure unless an approved revision is made.
