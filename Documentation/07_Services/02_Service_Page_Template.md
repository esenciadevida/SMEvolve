# SMEvolve Services Specification
## Part 2 – Service Page Template

**Project Name:** SMEvolve

**Website:** https://smevolve.tech

**Version:** 1.0

**Document Type:** Service Page Template

---

# Purpose

This document defines the standard structure that every SMEvolve service page must follow.

It ensures consistency in design, user experience, accessibility, SEO, and implementation.

Every service page should inherit this structure unless a documented exception is approved.

---

# AI Implementation Instructions

Before implementing any service page:

1. Read the AI Constitution.
2. Read the PRD.
3. Read the Information Architecture.
4. Read the Design System.
5. Read the Brand Messaging document.
6. Read the Services Master Specification.
7. Follow this template exactly.

Do not invent services, pricing, client statistics, guarantees, certifications, or unsupported claims.

---

# Standard Page Flow

Every service page must follow this order.

1. Hero

2. Service Overview

3. Problems We Solve

4. Our Solution

5. Key Features

6. Benefits

7. Technologies We Use

8. Development Process

9. Frequently Asked Questions

10. Related Services

11. Final Call To Action

---

# Hero

Purpose

Immediately explain:

- What the service is.
- Who it is for.
- Why it matters.

Include:

- H1
- Supporting paragraph
- Primary CTA
- Secondary CTA
- Supporting illustration or visual

---

# Service Overview

Explain:

- What the service includes.
- Typical business use cases.
- Expected outcomes.

Avoid technical jargon.

Focus on business value.

---

# Problems We Solve

Clearly identify the common business challenges that the service addresses.

Each problem should describe:

- The challenge
- Its impact
- Why it matters

This section should help visitors recognize their own situation.

---

# Our Solution

Explain how SMEvolve approaches solving those challenges.

Focus on:

- Collaboration
- Planning
- Customization
- Long-term scalability
- Maintainability

---

# Key Features

Display the major capabilities of the service.

Use responsive feature cards.

Each feature should include:

- Icon
- Title
- Short description

---

# Benefits

Explain the measurable business benefits.

Examples:

- Better customer experience
- Increased efficiency
- Improved online visibility
- Easier management
- Greater scalability
- Long-term cost savings

Benefits should focus on business outcomes rather than technical specifications.

---

# Technologies We Use

Present the technologies relevant to the service.

Display them using reusable technology badges or cards.

Only include technologies that are genuinely relevant to the service.

---

# Development Process

Reuse the standard SMEvolve development process established throughout the website.

Do not create a different process for each service.

---

# Frequently Asked Questions

Include FAQs that are specific to the service.

Questions should address:

- Scope
- Timeline
- Maintenance
- Customization
- Pricing (where appropriate)
- Support

---

# Related Services

Recommend 3–4 complementary services.

This section should encourage further exploration and strengthen internal linking.

---

# Final Call To Action

End every service page with a strong but friendly CTA.

Primary:

- Get a Free Quote

Secondary:

- Contact Us
- Chat on WhatsApp

---

# Design Requirements

Every service page should:

- Follow the Design System.
- Reuse existing Blade components.
- Maintain generous whitespace.
- Be visually consistent with the Homepage and About page.
- Be easy to scan.

---

# Accessibility

Ensure:

- Semantic HTML
- Proper heading hierarchy
- Keyboard accessibility
- Meaningful alt text
- Visible focus states
- WCAG AA compliance where practical

---

# SEO

Every service page should include:

- Unique page title
- Meta description
- Canonical URL
- Open Graph metadata
- Structured data where appropriate
- Internal links
- Descriptive headings

Content should prioritize user intent over keyword density.

---

# Performance

Reuse Blade components.

Lazy-load images.

Minimize JavaScript.

Avoid duplicate markup.

Target Lighthouse scores above 90 where practical.

---

# Acceptance Criteria

Every service page is complete when:

- All required sections are present.
- Messaging aligns with the Brand Messaging document.
- Accessibility requirements are met.
- SEO principles are followed.
- Components are reusable.
- The page is fully responsive.
- Calls to action are clearly presented.

---

# Revision Policy

Future services should reuse this structure unless a documented exception is approved.
